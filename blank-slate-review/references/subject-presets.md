# 盤點對象預設

> 何時讀：填委託書的「階段 1 表形狀」與「判定與等級定義」兩欄時，依盤點對象類型取一組；對象不在三組之內時，照〈自訂一組預設〉的欄位自己填一組，不要空著派。

本檔章節：〈預設一：用例與資料契約〉〈預設二：API 與同步協定契約〉〈預設三：測試計畫〉〈自訂一組預設〉。每組五欄：輸入白名單怎麼挑、停讀線常落在哪、階段 1 表形狀、起頭情境、必修與可改判準。

## 預設一：用例與資料契約

**適用**：被審對象是用例文件（use case）加資料契約（DDL、不變式、事件目錄），委託方想知道漏了哪些場景與跨領域互動。

| 欄 | 內容 |
|----|------|
| 輸入白名單怎麼挑 | 取「被審對象之前」的文件：專案定錨、訪談決策記錄、提案的範圍與驗收。判準：這份文件寫成的時候，被審對象還不存在 |
| 停讀線常落在哪 | 決策記錄的補記——「建立用例後」「審查後」這類標題之後的段落是依被審對象寫的；提案 frontmatter 的用例清單與缺口表 |
| 階段 1 表形狀 | 表一 用例清單：編號／行為者／觸發／目標／觸及領域／來源。表二 跨領域情境：編號／方向（A→B）／觸發動作／另一邊應觀察到／來源。表三 長時間尺度與生活事件：編號／情境／系統應如何表現／可能出問題處／觸及領域／來源 |
| 起頭情境（表三） | 長期沒開、換時區、換裝置、搬主機、從備份還原到舊時點、資料匯出、誤刪後回復、參照資料改名與合併重複、規則變更後既有資料、時鐘錯誤、本機資料損毀、兩台裝置都離線很久、隱私情境、一年後回頭查、批次重新分類 |
| 必修 | 需要新增或修改欄位、表、不變式、事件、跨領域查詢、同步協定 |
| 可改 | 只需補用例步驟、功能需求描述、UI 或設定，資料契約不動 |

**行為者欄要列機器角色**：同步器、伺服器排程、本機提醒、後台。使用者操作的用例通常寫得最齊，缺的多半是機器角色的失敗路徑。

**跨領域表的方向要寫反向**：A→B 寫了之後問 B→A——「在 B 直接完成由 A 產生的東西，A 知道嗎」。這一問在實例中找出了三項必修。

## 預設二：API 與同步協定契約

**適用**：被審對象是端點規格、請求與回應格式、錯誤碼、狀態機、重試與冪等規則。

| 欄 | 內容 |
|----|------|
| 輸入白名單怎麼挑 | 領域模型與事件目錄（協定要搬運的東西）、部署形態（誰呼叫誰、在哪個網路）、既有用戶端的能力限制 |
| 停讀線常落在哪 | 介面規格章節本身；標 inferred 或 draft 的端點表；依端點寫成的用戶端流程說明 |
| 階段 1 表形狀 | 表一 呼叫情境：編號／呼叫方／觸發／期望結果／失敗時呼叫方怎麼辦。表二 狀態與版本：編號／雙方各自持有的狀態／哪一方先變／另一方如何得知／不一致時以誰為準。表三 壓力情境：編號／情境／協定應如何表現／可能出問題處 |
| 起頭情境（表三） | 回應前斷線重送、雙方版本不同、伺服器回退到舊狀態、呼叫方身分被撤銷後仍有待送資料、時鐘偏差、單筆被拒而整批已部分套用、游標或序號失效、大量積壓、同一資料兩方同時改 |
| 必修 | 需要改請求或回應格式、錯誤碼清單、狀態機、冪等鍵、游標語意 |
| 可改 | 只需補文件描述、範例、呼叫方的 UI 提示 |

**狀態表要問雙向**：協定文件通常只寫「推」的方向（用戶端→伺服器）的錯誤處理；「拉」的方向遇到未知欄位、未知類型時的行為常常沒寫。

## 預設三：測試計畫

**適用**：被審對象是測試計畫、測試案例清單、追溯矩陣，委託方想知道哪些用例沒有測試、哪些測試沒有鑑別力。

| 欄 | 內容 |
|----|------|
| 輸入白名單怎麼挑 | 用例與功能需求（測試要覆蓋的東西）、資料契約的不變式清單、部署與執行環境說明 |
| 停讀線常落在哪 | 測試計畫本身；追溯矩陣；依測試計畫寫成的覆蓋率報告 |
| 階段 1 表形狀 | 表一 應有的測試：編號／來源（用例步驟、不變式、錯誤碼）／輸入／預期輸出／層級（單元、整合、實機）。表二 鑑別力要求：編號／守衛或旗標／該紅的輸入／對照輸入。表三 環境與時序：編號／測試依賴的外部因素（時鐘、網路、檔案、隨機、順序）／隔離方式 |
| 起頭情境（表三） | 時區與日光節約、兩台裝置離線後合併順序隨機、網路中斷重送、資料庫從備份還原、大量資料下的回應時間、權限被拒、外部服務不可用 |
| 必修 | 缺整類測試（某層級、某不變式、某錯誤碼完全沒有），或既有測試對目標功能無鑑別力 |
| 可改 | 補單一案例、改斷言寫法、補環境隔離 |

**鑑別力表要獨立於覆蓋表**：一個測試可以在追溯矩陣上「已覆蓋」而對目標功能失效時不翻紅；兩軸各自檢查。判準見 `test-assertion-design` skill 的鑑別力規則。

## 自訂一組預設

對象不在上面三組時，照下表填一組，寫進委託書：

| 欄 | 填法 |
|----|------|
| 輸入白名單怎麼挑 | 列出被審對象的「上游」文件：它依據什麼寫成 |
| 停讀線常落在哪 | 列出上游文件裡「依被審對象回寫」的段落 |
| 階段 1 表形狀 | 至少三張：對象的正常路徑清單、對象與其他東西的互動（含反向）、時間與環境壓力情境；每張都有編號與來源欄 |
| 起頭情境 | 三到五個，寫在委託書裡讓冷讀方擴充 |
| 必修與可改 | 必修＝改到結構（欄位、格式、狀態機、分類）；可改＝改到描述。以被審對象的「結構層」是什麼來定義 |
